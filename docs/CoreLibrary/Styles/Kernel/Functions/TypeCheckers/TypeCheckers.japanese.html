文字列

isEmptyString

引数の値が空の文字列になっている時 だけtrueを返し、其れ以外の場合には falseを返す。

簡易な関数ではあるが、他のStylus関数やミックスイン を開発する時役に立つ場合が有る。 例えば、isDimensionlessQuantityという他の値の型確認系の関数を実装する時に 利用された。

isDimensionlessQuantity(value)

  return typeof(value) == "unit" && isEmptyString(unit(value))

isNonEmptyString

引数の値が空の文字列に なっていない時だけtrueを返し、其れ以外の場合には falseを返す。

isNonEmptyString(X)は!isEmptyString(X)に 同等ではない。 上述通り、isNonEmptyString(X)は引数の値が 文字列だが空でない時だけtrue を返し、!isEmptyString(X)は引数の値 が文字列になっていない時にも trueを返す。

!isNonEmptyString(X)という利用もよく有る。 ２重否定（「non」を含めて）は読みにくいが、空の文字列以外の 値を除外する機能は需要が有る。

isString

引数の値が文字列になっている時だけ trueを返す、但し文字数は不問で、 0文字の時もtrue。 typeof(value) == "string"の短い同等。

量

殆どのプログラミング言語と違って、CSSプリプロセッサになってるStylusは一般の数 を取り扱っているのではなく、量を取り扱い、此れは次元量・無次元量の ２種類が在る。 何方をtypeof()に渡しても、返す結果は"unit"なので、 次元量か無次元量か明確にする必用が有る時追加の確認が必用。 此の目的の為に、下記の関数の中、isDimensionalQuantityと isDimensionlessQuantityも提供。 尚、isDimensionalOrDimensionlessQuantity関数は typeof(x) == "unit"の同等になってはいるが、和訳すると、 trueが次元量の時も、無次元量の時 も返される事が明確。

isDimensionalOrDimensionlessQuantity

引数は次元量又は無次元量になっている時 trueを返す、さもなくばfalseを返す。 typeof(x) == "unit"に同等だが、和訳すると、 次元量に確認されるか、無次元量に確認されるか（此の場合は両方）、明確に成る。

log(isDimensionalOrDimensionlessQuantity(2px)) // true
log(isDimensionalOrDimensionlessQuantity(2))   // true

isDimensionalQuantity

引数は次元量になっている時だけtrueを返す、 さもなくばfalseを返す。 但し、0を次元量として見做すかどうか、２個目の 引数で指定しなければいけない。 CSSの基礎に依ると、単位を関係なく量は 0の時単位を省略しても良い。 つまり、0pxも、0rem、 現在のCSSがサポートされる中の他の単位も 0に同等。

isDimensionalQuantity(2px, "MUST_CONSIDER_DIMENSIONLESS_ZERO_AS_DIMENSIONAL_QUANTITY") // true
isDimensionalQuantity(2, "MUST_CONSIDER_DIMENSIONLESS_ZERO_AS_DIMENSIONAL_QUANTITY")   // false
isDimensionalQuantity(0, "MUST_CONSIDER_DIMENSIONLESS_ZERO_AS_DIMENSIONAL_QUANTITY")   // true
isDimensionalQuantity(0, "MUST_NOT_CONSIDER_DIMENSIONLESS_ZERO_AS_DIMENSIONAL_QUANTITY") // false
第２引数は必須
第１引数の値に関係無く、 第２引数の指定は必須。

上記の例だと、第１引数の値はハードディスクされたが、実践上 常に動的（事前に不明）なので、 第２引数は必須になっている。

isDimensionlessQuantity

引数は無次元量になっている時に限ってtrueを返す、 さもなくばfalseを返す。 但し、0はいつも無次元量として取り扱われる事になっている。

isDimensionlessQuantity(2px) // false
isDimensionlessQuantity(2)   // true
isDimensionlessQuantity(0)   // true

isNaturalNumber

引数は無次元量であり、自然数になっている時に限って trueを返す、さもなくばfalseを返す。

0が自然数にはなっていない事に気を付ける。
p(isNaturalNumber(1))    // true
p(isNaturalNumber(0))    // false
p(isNaturalNumber(1.1))  // false
p(isNaturalNumber(1e+1)) // false
p(isNaturalNumber(-1))   // false

真偽

取り組み型安全性が無い言語として、Stylusは 非真偽型の値を自動的に真偽型に変換する 場合が有る（例えば、条件的表現に於いて）。 とは言え、Stylusの振る舞いは開発者達が慣れたJavaScriptらしい振る舞いと 異なる事が有る。 例えば、Stylus言語だと、if someVariableに於いて someVariable変数が初期化されていなくても、trueが 返される。

definedVariable = true

if definedVariable

  p("明かに、コンソールに出力される")


if undefinedVariable

  p("'typeof(undefinedVariable)'が'ident'で、falseに変換されていないので、此方もコンソールに出力される")

予想外のバグを避けるには、someVariable == trueか someVariable == falseの様に明示的に比較する 推薦だが、当ライブラリが提供しているisTrue(someVariable)と isFalse(someVariable)はより短い選択肢。

isBoolean

typeof(x) == "boolean"比較表現の短い代替物。 此処でxは未宣言の場合を含めて適当な変数。

isFalse

x == false比較表現の代替物。 此処でxは未宣言の場合を含めて適当な変数。

isTrue

x == true比較表現の代替物。 此処でxは未宣言の場合を含めて適当な変数。

Null系

Stylusに於いてはnull値と関連している欠陥が何件が有る。 当関数群は上記の欠陥に依る落とし穴を避けて安全にnull・非null確認機能を提供。 より明確な情報が必要な場合、下記の理論を参考迄に。

【最少理論】 Stylusに於けるnull値

`null`キーワード

下記のコードを考察しておこう。

sample1 = null
p(sample1)
p(typeof(sample1))
p(sample1 == null)
p(typeof(sample1) == "null")

今のところは、Stylusの振る舞いに異常が無い。

inspect: null
inspect: 'null'
inspect: true
inspect: true

オブジェクトの存在していないプロパティー

下記のコードを考察しておこう。

sample1 = null
p(sample1)
p(typeof(sample1))
p(sample1 == null)
p(typeof(sample1) == "null")

今のところは、Stylusの振る舞いに異常が無い。

inspect: null
inspect: 'null'
inspect: true
inspect: true

残りの引数しかない関数・ミックスイン

下記のコードを考察しておこう。

sampleFunction1(parameters...)

  sample3 = parameters

  p(sample3)
  p(typeof(sample3))
  p(sample3 == null)
  p(typeof(sample3) == "null")

sampleFunction1()

異常は此処から始まる。 sample3 == nullは偽になってはいるが、 typeof(sample3) == "null"は真。

inspect: ()
inspect: 'null'
inspect: false
inspect: true

最初位置の場合を除き残りの引数持ちの関数・ミックスイン

下記のコードを考察しておこう。

sampleFunction2(parameter, restParameters...)

  sample4 = restParameters

  p("Checkpoint1")
  p(sample4)
  p("Checkpoint2")
  p(typeof(sample4))
  p(sample4 == null)
  p(typeof(sample4) == "null")

sampleFunction2("TEST")

出力は下記通りになっている。

inspect: "Checkpoint1"
inspect: "Checkpoint2"
inspect: 'null'
inspect: false
inspect: true

此処下記の異常に気付くべき。

  • p(sample4)は無視された。
  • typeof(sample4) == "null"は真になっているが、 sample4 == nullは嘘。

上記の実験に基づいた結論は、nullと直接比較する事は 安全ではない事。 代わりに、typeofというネイティブ 関数を用いて、 typeof(x) == "null・typeof(x) == "null の様に比較するべきだが、YDFが提供している関数がより短い。

isNotNull

引数の値がnull以外の場合に trueを返し、nullになっている場合に 限ってfalseを返す。 上記の解説通り、nullと明示的な比較は予想通り動いているとは限らないので、 isNotNullはx != nullと同じ効果では ない。

isNull

引数の値がnullになっている場合に限って trueを返している、さもなくば戻る値はfalse。 上記の解説通り、nullと明示的な比較は予想通り動いているとは限らないので、 isNotNullはx != nullと同じ効果では ない。

其の他

isCalcExpression

引数がStylusリテラルになり、calc(から始める場合 に限ってtrueを返している、さもなくば戻る値は false。 calc表現専用のデータ型がStylus上存在していないが、 リテラルがcalc表現を代表しているか、分析する事は可能。 其れは、此の関数がやっている事である。

isFunction

引数の値が関数になっている場合に限ってtrue を返している、さもなくば戻る値はfalse。 typeof(x) == "function"の短い代替。

isIdentifier

引数の値が識別子になっている場合に限ってtrue を返している、さもなくば戻る値はfalse。 typeof(x) == "function"の代替。

isObject

引数の値が関数になっている場合に限ってtrue を返している、さもなくば戻る値はfalse。 typeof(x) == "object"の短い代替。
